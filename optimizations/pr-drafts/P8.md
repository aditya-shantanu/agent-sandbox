## PR title

`fix(controller): release leader lease on graceful shutdown`

## PR body

#### What this PR does / why we need it

`LeaderElectionReleaseOnCancel` is unset today, so on every rolling update the
outgoing controller leaves its Lease to expire and the incoming replica waits out
the full **15s LeaseDuration with no active controller**. In the 300-claim
warm-adoption benchmark environment a routine rolling update left the system
leaderless for ~15s; with the lease released on clean shutdown, handover is
**~0-2s**. At a sustained 500 claims/s, a 15s leaderless window is ≈7,500 claims
queueing behind a routine deploy.

Changes:

- Set `LeaderElectionReleaseOnCancel: true` in the manager options.
  controller-runtime documents the precondition — the binary must terminate
  immediately once the manager stops — and it holds here: `mgr.Start(ctx)` is the
  last statement of `main()`. **Crash failover is unchanged by design:** only clean
  exits release the lease early; lease expiry still protects against split brain.
- Extract the manager-options construction into `buildManagerOptions`
  (behavior-preserving refactor) and add unit tests pinning
  `LeaderElectionReleaseOnCancel`, the leader-election ID, and the
  enable/namespace pass-through, so the setting cannot silently regress.

#### Performance (A/B protocol; run deferred until filing)

Planned measurement on the standard tuned 6-node kops A/B cluster (identical
cluster tuning for both legs; one cluster reused; clean instrumentation): deploy
the baseline image, drive a steady claim trickle, `kubectl rollout restart` the
controller Deployment, and measure the leaderless window (old leader's last
renewal → new leader's acquire, from Lease transitions and controller logs) plus
the claim-ready stall over the window — baseline vs this branch. Expected:
~15s (LeaseDuration expiry) vs ~0-2s. Table to be inserted here before filing.
