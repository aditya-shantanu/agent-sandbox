# PR title: perf(sandbox): opt-in write-behind coalescing for recoverable metadata writes
Branch: aditya-shantanu:upstream-p6-write-behind-coalescing

#### What this PR does / why we need it:

**Problem.** During a claim burst, the sandbox controller's recoverable metadata-only writes compete with latency-critical writes for APF seats: in a 300-claim warm-adoption benchmark we measured ~846 writes/s offered against a ~600-900/s seat-limited service rate, so every avoidable write in the burst window directly delays a critical one. On top of that, repeated mutations to the same object (level-triggered redeliveries recomputing the same drift) each pay a full write round-trip today.

**Mechanism.** This adds `internal/writebehind`, a small bounded coalescer for metadata-only (labels/annotations) writes, and routes exactly two sandbox-controller writes through it — both recoverable, i.e. recomputed verbatim from informer state by the next level-based reconcile:

- the pod metadata reconciliation patch on the warm-pool adoption path (warm-pool label prune + `cluster-autoscaler.kubernetes.io/safe-to-evict` strip + propagated-keys tracking), and
- the sandbox `agents.x-k8s.io/pod-name` annotation write.

Properties:

- **Opt-in window** (`--sandbox-write-behind-window`): pending mutations to the same object merge into ONE JSON merge patch, flushed within the window.
- **≤1s pod bound**: pod patches additionally flush within `min(window, 1s)`, so the safe-to-evict strip cannot lag the cluster autoscaler (scan intervals are 10s+).
- **Shutdown drain**: pending patches flush on graceful manager stop.
- **Level-based crash recovery**: a crash before flush is recovered by the next reconcile re-detecting the drift and re-issuing the mutation — the same self-healing the synchronous path relies on.
- **Bounded memory**: beyond a cap of distinct pending objects, writes degrade to synchronous inline patches.
- **Stays synchronous**: status writes, creates/deletes, and ownership transfers are never routed through the coalescer.

**Default 0 = off.** With the flag unset no flusher is constructed and the controller runs the identical, fully synchronous stock write path (pinned by `TestWriteBehindDisabledIsSynchronous` and the flag-off reference run in `TestWriteBehindCoalescesAdoptionPodPatch`, which also proves the flushed end state is identical to the synchronous one).

#### Which issue(s) this PR is related to:

Ref #350, Ref #594

#### Release Note

```release-note
Added an opt-in `--sandbox-write-behind-window` flag (default 0 = disabled) to the sandbox controller. When set (e.g. 250ms), recoverable metadata-only writes — the pod metadata reconciliation patch and the sandbox pod-name annotation — are coalesced into one merge patch per object and flushed within the window; pod patches always flush within min(window, 1s). The default keeps today's fully synchronous write behavior.
```
