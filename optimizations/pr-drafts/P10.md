## PR title

`feat(router): namespace/name cache resolution`

## PR body

#### What this PR does / why we need it

The sandbox-router resolves a request's target sandbox via its UID cache and
otherwise falls back to DNS — the per-sandbox headless Service record. That has
two measured/observed costs:

- The DNS fallback is the 502/NXDOMAIN failure mode of #883 (missing or stale
  per-sandbox Service records during churn).
- It makes per-sandbox Services load-bearing for routing. Each per-sandbox
  Service costs ~2 EndpointSlice writes over a sandbox lifecycle — ~20-25% of API
  churn writes in a 300-claim warm-adoption benchmark with Services enabled.

This PR adds a namespace/name index to the router's sandbox cache and re-orders
resolution: **PodIP header → UID cache → namespace/name cache → DNS last**. With
name-based cache resolution, `spec.service: false` — an existing API field, no
CRD change — becomes fully viable: sandboxes without a Service are routed from
cache and never touch DNS.

Implementation notes: the name map lives alongside the UID map with a
UID-guarded delete (a late delete event for a replaced pod cannot evict a
same-named successor's mapping), and the proxy's `ErrorHandler` invalidates a
name-cache entry whose IP fails to dial. Unit tests cover the cache index
(add/lookup/invalidate/stale-delete guard) and the full resolution order;
an integration test covers dial-failure invalidation.

This is complementary to the Envoy-based routing RFC (#850): whichever proxy
implementation wins, name-based resolution removes the DNS/Service dependency
for service-free sandboxes.

#### Performance (A/B protocol; run deferred until filing)

Planned measurement on the standard tuned 6-node kops A/B cluster (same cluster
tuning both legs, clean instrumentation): 300-claim warm burst with per-sandbox

router; report (a) API churn write counts — per-sandbox Service +
~2 EndpointSlice writes eliminated per sandbox, (b) router first-request
